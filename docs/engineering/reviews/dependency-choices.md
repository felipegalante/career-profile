# Dependency assessment

Status: **PLANNED recommendations**, not adopted dependencies. Introduce each only after its phase review and verify exact peer/runtime compatibility in the locked install. No dependencies were added during this audit.

## Existing stack

Preserve React/TypeScript/Vite/Tailwind, Fastify 5, GraphQL Yoga, PostgreSQL 16 and Drizzle on pg. The starter uses them appropriately for a modular monolith. Yoga integration is absent, which is acknowledged foundation work, not evidence for replacing Yoga. `@fastify/cookie`, Drizzle and its kit are declared but not fully wired. Do not remove them as “unused” when their accepted purpose is upcoming.

Read-only registry checks on the review date found all 24 distinct baseline versions declared across manifests/packageManager. No installation or full peer-resolution audit occurred. The following are the material compatibility issues, rather than speculative claims that recent version numbers do not exist:

- Repository requires Node >=24 but current shell is 22.22.3.
- Declared jsdom 30.0.0 requires Node `^22.22.2 || ^24.15.0 || >=26.0.0`; therefore the declared Node 24 minimum is too broad. Pin a supported/tested 24 patch at least 24.15.0.
- Node types 26 should align with the selected Node 24 runtime or explicitly restrict runtime API use.
- There is no lockfile, build verification, or installed graph. `pnpm install --frozen-lockfile` becomes the CI rule after Phase 00 generates and reviews the initial lockfile.

Registry evidence: [jsdom 30 metadata](https://registry.npmjs.org/jsdom/30.0.0), [Node types metadata](https://registry.npmjs.org/@types%2fnode/26.2.0), [pnpm metadata](https://registry.npmjs.org/pnpm/12.4.2). Registry metadata establishes publication/engines only, not security or suitability.

## Additional choices

| Concern | Recommendation / phase | Project-specific reason | Why built-in/custom or alternatives are insufficient/unnecessary | Cost and review gate |
| --- | --- | --- | --- | --- |
| Routing | `react-router`, declarative SPA mode / 01 | Auth guards, onboarding, nested Account tabs and browser history need stable route composition. | Ad-hoc pathname switches miss reload/history/focus contracts. No need for SSR, file routing or a second application framework. | One runtime library; verify Vite build and deep-link hosting. [Routing docs](https://reactrouter.com/start/declarative/routing). |
| Form state | Controlled React state first; introduce `react-hook-form` only if measured repetitive field/error work warrants it / 05 | Current forms are modest, but dependent catalogs must integrate explicit domain state and preserve server errors. | A generic config-driven form engine is unnecessary. RHF is a candidate for dirty/field state, not the owner of catalog search or business rules; don't add it solely because forms exist. | No added package initially; reassess after first full form. [RHF guide](https://react-hook-form.com/get-started). |
| Runtime/schema validation | Native explicit env/auth checks first; evaluate `zod` for repeated nested input parsing in 03–05 | Config, catalog one-of selections, nested forms and seed input need runtime parsing beyond TypeScript/GraphQL. | GraphQL type validation cannot express date order/one-of/ownership. Hand-written domain invariants still needed; no automatic DB-schema-to-product validation. | Adopt only if two concrete parsing boundaries benefit; no duplicate GraphQL validation or unused shared-schema layer. Avoid sharing DB-only types with web. [Zod](https://zod.dev/). |
| GraphQL transport/client | Native typed `fetch` in 01; evaluate `@tanstack/react-query` in 03/04 | Credentials, typed errors, cancellation, parent-sensitive query keys, mutation invalidation and Skills rollback need one server-state owner. | Fetch is sufficient transport but hand-building a cache/invalidation/retry layer is costly. Apollo/urql offer valid GraphQL caches, but normalized graph caching is not required for this single-viewer app; don't install alongside Query. | Compare actual search/invalidation/optimistic code before adoption; viewer/login alone does not justify a cache package. If adopted, logout isolation and optimistic race tests are required. [GraphQL with Query](https://tanstack.com/query/latest/docs/framework/react/graphql). |
| GraphQL type generation | `@graphql-codegen/cli` + client preset with real auth operations / 01; resolver plugin only if SDL/module duplication warrants it | Spec naming already drifts; generate operation inputs/results from assembled SDL once actual operations exist. Types do not replace authorization or runtime validation. | Dev tooling and generated artifacts; check deterministic regeneration in CI; no live DB/server required for codegen. [Client preset](https://the-guild.dev/graphql/codegen/plugins/presets/preset-client). |
| Drag/drop | **Adopted:** React Aria `useDrag`/`useDrop` (ADR 0012) | Required cross-lane pointer movement needs category-constrained drop targets, cancellation and announcements. | Native drag events under the hood work with mouse and touch long-press; the Move menu remains the keyboard and assistive-technology path, so keyboard drag mode is off. A second drag library would duplicate React Aria. | Verified by Playwright drags on Chromium, Firefox and WebKit. |
| Password hashing | `argon2` using Argon2id / 01 | Provides encoded hash/verify/rehash functions and avoids bespoke credential encoding. | Node crypto contains primitives, but availability/stability depends on pinned Node and a correct password envelope still needs care. Scrypt via Node is a fallback if native deployment is blocked, not a reason to invent cryptography. | Native binary/build deployment check; calibrate memory/time and cap concurrent hash work; retain policy/version information. [node-argon2](https://github.com/ranisalt/node-argon2), [Node crypto](https://nodejs.org/api/crypto.html). |
| Sessions | Existing `@fastify/cookie` + small DB-backed opaque-session repository + Node crypto / 01 | Server invalidation, reset generation checks and setup-only grants match the domain exactly. | No JWT/localStorage or self-contained encrypted-cookie session; those complicate immediate server revocation. Full auth framework has no required providers here. | Custom session logic is small but security-sensitive; cover token hashing, expiry, rotation, CSRF and races. Do not misuse SESSION_SECRET as the password hasher. |
| Auth rate limiting | `@fastify/rate-limit` as transport layer plus service-level attempt policy / 01 | Cookie login/reset endpoints need request throttling and operation-aware control. | IP-only limiter is insufficient for aliases/batched GraphQL operations; custom service counter is still needed. No Redis required for one instance; multi-instance deployment must choose shared counters. | Must verify proxy identity and limits without permanently locking out legitimate users. |
| Date handling | No date library initially / 05 | Calendar dates, year/month and integer years can be validated with explicit codecs and formatted using Intl. | JS Date parsing must not invent timezone/day precision. date-fns/Luxon would be added only for concrete timezone/arithmetic needs absent here. | Tests for leap dates/month ordering/locale output; Q07 before persistence. |
| Icons | **Adopted:** local icon set in `ui` with the exact artifact paths | Shell, focus, form and status icons share one SVG vocabulary. | Stock icon packages draw different paths from the reviewed artifacts. | Decorative by default; icon-only buttons require an accessible name. |
| Accessible primitives | **Adopted:** `react-aria-components` ~1.21 (ADR 0012) | Dialogs, menus, combobox, tabs, palette, tooltip, file drop and drag need tested focus and keyboard behavior. | Unstyled, so the artifact CSS applies unchanged; one headless library only. Its toast API is still unstable, so toasts are implemented in `ui`. | Upgrades are deliberate (tilde range) and reviewed for deprecated props. |
| Fonts | **Adopted:** `@fontsource/geist` and `@fontsource/geist-mono` | Geist and Geist Mono are the rendered type (Q11). | Self-hosting removes the runtime request to Google Fonts and keeps CI screenshots deterministic. | OFL-1.1; weights 400/500/600 and 400/500. |
| Shared client state | No Redux/Zustand / all initial phases | Route/query state, local form state and shell context cover current needs. | An extra global store duplicates server truth and complicates logout cleanup. | Reassess only for demonstrated cross-feature local state complexity. |
| DataLoader | Defer until query-count evidence / 05–11 | Batched repositories can retrieve source previews/catalog labels without per-node resolvers. | A loader everywhere hides inefficient shapes; global loaders risk private-value leakage. | If adopted, request-local and viewer-aware only. |
| Data table | Shared presentational parts in `ui` (toolbar, filters, sortable headers, pagination, scroll region) + a local controller / 10 | One admin table with fixed columns and server queries. | No editable spreadsheet, grouping or large client dataset; TanStack Table is not necessary. | Admin owns query, URL and sort state. |
| Browser/a11y tests | **Adopted:** Playwright with `@axe-core/playwright`; computed-style parity against the artifacts; Linux screenshot baselines in CI | Real pointer drag, focus trapping, responsive overflow and fidelity to the artifacts need browser evidence beyond jsdom. | RTL/Vitest with `@testing-library/user-event` stay the fast behavior layer. | Axe on every gallery page; manual screen-reader checks remain necessary. |

Any new library is a phase-level engineering recommendation; product approval is needed for changed behavior, not routine compatible package selection. Do not preselect storage, job queue, parsing or model providers before Q10 closes for planned Resume phases.
