# Dependency assessment

Status: **PLANNED recommendations**, not adopted dependencies. Introduce each only after its phase review and verify exact peer/runtime compatibility in the locked install. No dependencies were added during this audit.

## Existing stack

Preserve React/TypeScript/Vite/Tailwind, Fastify 5, GraphQL Yoga, PostgreSQL 16 and Drizzle on pg. The starter uses them appropriately for a modular monolith. Yoga integration is absent, which is acknowledged foundation work, not evidence for replacing Yoga. `@fastify/cookie`, Drizzle and its kit are declared but not fully wired. Do not remove them as “unused” when their accepted purpose is upcoming.

Read-only registry checks on the review date found all 24 distinct baseline versions declared across manifests/packageManager. No installation or full peer-resolution audit occurred. The following are the material compatibility issues, rather than speculative claims that recent version numbers do not exist:

- Repository requires Node >=24 but current shell is 22.22.3.
- Declared jsdom 30.0.0 requires Node `^22.22.2 || ^24.15.0 || >=26.0.0`; therefore the declared Node 24 minimum is too broad. Pin a supported/tested 24 patch at least 24.15.0.
- Node types 26 should align with the selected Node 24 runtime or explicitly restrict runtime API use.
- There is no lockfile, build verification, or installed graph. `pnpm install --frozen-lockfile` becomes the CI rule after Phase 00 generates and reviews the initial lockfile.

Registry evidence: [jsdom 30 metadata](https://registry.npmjs.org/jsdom/30.0.0), [Node types metadata](https://registry.npmjs.org/@types%2fnode/26.2.0), [pnpm metadata](https://registry.npmjs.org/pnpm/12.4.2). Registry metadata establishes publication/engines only, not security or suitability.
