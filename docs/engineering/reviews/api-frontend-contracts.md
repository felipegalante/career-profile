# Proposed API and frontend contracts

Status: **PLANNED**, with product gates in [readiness review](architecture-readiness.md). No SDL, resolver or component is implemented here.

## Backend organization

Keep `api/src/app.ts` as an injectable app factory and `server.ts` as configuration/listen/shutdown wiring. Proposed modules: `auth`, `profile`, `catalogs`, `skills`, `experience`, `education`, `certifications`, `focus`, `admin`. Each owns SDL/resolvers, application services, validation and domain-specific repositories. Shared infrastructure owns DB transaction context, error translation and request identity. Normalization/ranking helpers are extracted when at least two concrete catalog repositories need them. No resolver-to-resolver calls; no generic repository that accepts arbitrary table names. Cross-domain source saves call Skills application functions with the same transaction handle.

Feature module assembly should be explicit. Do not introduce runtime plugin discovery, dependency-injection containers, a message bus, federation or microservices for this product. `/healthz` and an optional readiness endpoint remain operational only. Mount Yoga at `/graphql` and test its real Fastify request/response/cookie adapter with `inject()`.

## Schema contract

- `viewer: Viewer` is null when unauthenticated. Identity and onboarding state are explicit. Only authorized viewer fields expose profile collections; admin listing uses a narrow `AdminUserSummary`, not an unrestricted recursive user/profile graph. Never expose password hashes, grants, cookie tokens or private catalog metadata through admin list types.
- Proposed auth operations: `register(input)`, `login(input)`, `logout`, `setPassword(input)` and `completeOnboarding`. Typed auth outcomes distinguish established session vs setup only when Q01 proof is already valid. A bad account/password/grant remains generic; preserve AUTH-AC-004.
- Keep existing focused domain operation names from architecture: add/update/remove WorkExperience, Education and Certification; updateProfile; searchCompanies/searchJobTitles/searchInstitutions/searchMajors/searchDegreeTypes/searchCertificationBoards/searchCertifications/searchFocusAreas/searchSkills; updateProfessionalFocus; addSkill/addCustomSkill/removeSkill/updateSkillProficiency; adminUsers/adminCreateUser/adminResetPassword. Resolve Focus's `focusAreas` alias and Skills argument discrepancies in specs before generating client documents.
- `CatalogSelectionInput { catalogId, customLabel }` enforces exactly one nonblank value. No arbitrary `ownerId`, role, category or inferred source passed in self-service inputs. Domain fields have explicit names (`majorSpecialization`, `certificationBoard`); `certification` is the selected definition, `certificationId` is the optional external ID. Parse GraphQL IDs as UUIDs at validation boundaries where applicable.
- Parent searches accept the same selection shape so a local unsaved custom company/institution/board is usable. Parent IDs are checked for visibility before search; custom labels do not create rows. Results include canonical ID/label/origin or scope, relationship hint, and already-added state where relevant. Metadata must not disclose another user's private relation.
- Search inputs have `query`, `limit` (default 10, proposed maximum 25) and typed parent context. Q08 freezes rank order, normalization, empty-query behavior and match metadata. Match highlighting must be safely rendered text and support normalization-to-display offsets; it is not permission to render server HTML.
- `YearMonth`, `LocalDate`, `DateTime` scalars only if Q07 needs their distinct precision; validate serialized and literal inputs identically. Education year is a bounded integer. Avoid one permissive Date scalar for all concepts.
- Ordinary errors use stable `extensions.code` plus sanitized `fieldErrors [{ path, code, message }]` and request ID. Proposed codes: UNAUTHENTICATED, FORBIDDEN, VALIDATION_FAILED, NOT_FOUND, DUPLICATE_EMAIL, DUPLICATE_SKILL, INVALID_PARENT_SELECTION, CATALOG_VALUE_NOT_VISIBLE, CONFLICT, RATE_LIMITED, INTERNAL. Treat cross-owner entity IDs as inaccessible without revealing their content/existence beyond approved semantics.
- Domain mutations return the canonical changed entity. The frontend invalidates/refetches Skills after source-changing saves; do not duplicate the entire skill graph in Work/Education/Certification payloads. `removeSkill` returns a canonical `REMOVED` or `DISMISSED` outcome, enabling the client to remove the chip truthfully and offer Undo; a bare generic RemovePayload cannot distinguish them. Use expected revisions for whole-list Focus saves and optimistic Skills operations. Ordinary profile/record CRUD starts with atomic last-committed-write behavior, documented and tested; do not add revisions to every table by convention. Multi-field saves are pessimistic; only reversible low-risk operations use optimistic UI.

## Authentication and transport controls

Default to same-origin production hosting and Vite `/graphql` proxy locally. Cookies: opaque high-entropy token, HttpOnly, Secure outside local HTTP, SameSite=Lax (review if deployment topology changes), Path=/ and no Domain for host-only scope; production may use `__Host-` naming. Persist token hash, expiry, revoked state and credential generation. Define absolute lifetime (existing example seven days) and idle policy before authentication release. Never put tokens into localStorage.

Validate trusted Origin for cookie mutations and require a non-simple request/CSRF mechanism through Yoga/Fastify; do not rely solely on SameSite. Deny GET mutations and unsupported content types, constrain CORS to the approved origin, validate trusted-proxy settings, and ensure context resolves identity from server session. Check the chosen Yoga integration against [its CSRF documentation](https://the-guild.dev/graphql/yoga-server/docs/features/csrf-prevention).

Set operation/body bounds, selection-depth/alias cost limits, bounded table/search inputs, execution timeout and statement timeout before external exposure. Proposed initial budgets must be measured against actual Profile documents, not copied from a generic service. Count login/setup attempts at the application operation level as well as request/IP; aliases and batching must not bypass throttling. Redact Authorization, Cookie, Set-Cookie, passwords, grants, and GraphQL sensitive variables. Record request ID, operation name, duration and safe error code; no profile payload logging.

## Tables and pagination

Only Admin Users is a growable product table today. Design token/specimen tables are documentation; Profile records are cards, Skills are lanes, Focus is an ordered selected set, and catalog menus are bounded suggestions. No evidence justifies two pagination standards.

**Recommend offset/page pagination for Admin.** Its requirements explicitly include page numbers, page-size selection, exact total/range, arbitrary sorts and filters. Keyset cursors complicate random page access/total metadata without a demonstrated dataset size benefit. Revisit only with measured deep-offset cost; future job/history tables must justify their own contract.

Proposed `AdminUserListInput`: `page` (1-based default 1), `pageSize` (10/25/50/100, default 25), optional trimmed search (bounded length), role, onboarding status, sort field CREATED_AT or NAME, direction ASC/DESC. Role/onboarding sort is optional in the current spec; add only if approved. Return `rows`, `totalCount`, `page`, `pageSize`, `pageCount`, `rangeStart`, `rangeEnd`, `hasNextPage`, `hasPreviousPage`. For no matches range is 0–0; clamp a page invalidated by deletion/filtering and return the canonical page.

SQL: join `users` to its single profile; apply authorization before selection, parameterized name/email search and enum predicates; `onboarding_completed_at IS NULL/IS NOT NULL`; stable sort with unique ID tie-break; LIMIT/OFFSET. Count and rows use the same filters and transaction snapshot (read-only repeatable read or equivalent single-snapshot query). Avoid duplicating users through profile-collection joins. Default newest order is `created_at DESC, id DESC`; name sorting specifies null handling and deterministic collation with ID tie-break. Exact count and row range must agree.

URL query parameters preserve page/pageSize/query/role/onboarding/sort/direction. Search/filter/sort resets page to 1; back/forward restores controls and query. Page-size change follows the documented reset rule. Loading can preserve previous rows under an updating indicator; do not label stale rows as the newly requested page. An error preserves filters and provides Retry; empty database and no filter matches use distinct messages/actions.

## N+1 and query cost

Fetch per-user collections in bounded numbers of queries with joined/batched catalog labels and a single grouped source query for skills. Do not issue one source/catalog query per chip. Admin avoids fetching profile collections entirely. Add request-local DataLoader only if resolver composition actually creates repeated keyed loads; its keys/cache must include viewer context, never a global cache of private entities. Test query count as record counts increase. No subscriptions or live collaboration are required.

Profile collection size is not a new product cap. Measure synthetic large profiles before release and choose section-level progressive loading if necessary with new AC. Never silently truncate `Show all` data or present loaded-count as total. Keep exact skill totals in server projections.

## Frontend boundaries

Proposed `web/src/app` owns routing, providers, error boundary and shell; `features/<domain>` owns view/form/operations; the `@career-profile/ui` workspace package owns tokens, primitives, the shell and the shared presentational compositions (CatalogCombobox, ProfileRecordDialog, skill board, table parts) and never imports GraphQL, the router or domain rules. Admin keeps its table controller (query and URL state) local. Do not create empty module directories or a configurable component framework. Generated operation types sit at a clear API boundary. Avoid a second copy of server entities in a global store.

Routes: `/login`, `/register`, `/set-password`, `/onboarding`, `/profile`, `/profile/focus`, `/account?tab=profile|settings`, `/admin/users`. Implement direct-link/reload/back handling and meaningful route titles. Work/Education/Certification/Skills open within Profile; if approved focused surfaces are used, provide Back to Profile and preserve Profile scroll/state. Guards wait for viewer resolution (no unauthorized-content flash); failed network access is not equivalent to logout. Server authorization remains authoritative.

Use generated typed GraphQL documents over a small `fetch` transport with small viewer state in 01; evaluate TanStack Query at 03/04 when searches and mutation invalidation become real (one server-state owner). Query keys include viewer, operation, query and parent context. Clear private caches on logout/account change; cancel in-flight old-session requests so late results cannot repopulate them. Forms, combobox draft selections, active option, dialog state and drag position stay local. Sidebar collapse does not remount route content.

CatalogCombobox owns debounce (~250ms), cancellation/request-generation stale guard, correct parent-key invalidation, separate input vs selected value, controlled listbox, disabled already-added options, no-results/loading/error states and safe custom draft selection. Forms own parent compatibility and validation. Escape first closes its popover; a subsequent Escape may close the containing dialog. Never persist custom values on mere selection/cancel.

ProfileRecordDialog owns labelled dialog, initial focus, trap, restoration, safe Escape/close, scrollable body, mobile footer and shared error/submit structure. Explicit domain fields remain in domain forms; no field-configuration engine. Define pending-save close/cancel behavior and recoverable form errors. When a trigger disappears after deletion, restore focus to the next meaningful section action.

Command palette uses the same overlay system and a static authorized command list; no GraphQL global search is needed. Commands are role/context/capability filtered; Resume Tools becomes available with its active R1/R2 capability rather than as an early dead command. Arrow/Enter/Escape, active result announcement, focus restore and no modal stacking are mandatory. Cmd/Ctrl+B must preserve contenteditable bold behavior; normal inputs do not disable it. Visible triggers remain operable without shortcuts.

Skills optimistic movement is keyed by user-skill ID and revision. A manual-only onboarding selection and a dismissed inferred skill disappear immediately; persistence failure restores the prior chip/counts under SKL-AC-016. Use a brief Undo toast as the reversible removal pattern rather than a confirmation dialog. Avoid a generic optimistic transaction engine. Cancel affected queries, snapshot only affected entities/counts, serialize same-entity operations and reconcile canonical responses. An older failed move must not undo a later successful one. Remove during drag cancels drag; cross-category drops are rejected before mutation. Make × and Move separate semantic buttons, not nested drag activators. Announce the `REMOVED` or `DISMISSED` result, and expose inferred-source details through a focusable control.

Admin DataTable starts as local semantic HTML plus a typed controlled toolbar/pagination; no general spreadsheet/virtualization library. Use real buttons in sortable headers with `aria-sort`, a caption/accessibly named table, labeled filters, range live status, disabled boundaries and a named scroll region on mobile if horizontal scrolling is selected. Prefer section error boundaries to losing the entire Profile on one failed collection.

## Responsive/accessibility acceptance baseline

Check 320px and 390px phones, 768px tablet, 1280px desktop, text zoom and 400% reflow where applicable. Keyboard covers whole auth/onboarding/profile/admin journeys; VoiceOver covers dialog/combobox/status interactions. Focus never moves into a hidden dependent field or behind a blocking overlay. Provide error-summary links, field `aria-describedby` and `aria-invalid`, polite saves/search counts and assertive actionable errors without toast spam. Tables retain header associations; chips have sufficient target size/spacing; status is never color-only. Test touch scroll against drag activation and reduced motion. Automated checks supplement, rather than replace, manual screen-reader and real pointer drag tests.
