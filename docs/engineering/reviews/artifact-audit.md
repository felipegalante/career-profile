## Concrete browser findings

- At 390px, actual `admin/users.html` has `documentElement.scrollWidth = 575` and table parent `overflow-x: visible`. This is whole-page overflow, not a deliberately named table scroll container. Toolbar itself wraps usefully; preserve that improvement.
- Actual Profile hides its desktop sidebar below 860px without exposing the menu depicted by the separate mobile specimen. Navigation must be implemented as responsive app behavior, not by swapping unrelated demo pages.
- Education edit stacks fields well at 390px and retains footer actions in the sampled viewport. Test virtual-keyboard and long error text before accepting mobile dialog behavior.
- At 768px auth hides the illustration and retains a readable single-column form; desktop basics/set-password use consistent right-side professional-story graphics. Illustrations should be decorative/accessibly summarized appropriately, not duplicate every text node to screen readers.
- Palette DOM exposes a named dialog and textbox but generic command rows; script only opens/closes. Filtering, active option, Arrow/Enter activation and trap are not implemented. The page is a state specimen, not evidence of APP-AC-003 completion.
- Skills editor has real remove buttons and pointer drag listeners. The visual instruction to use Move does not create the missing Move control. UI-only removal is not a backend persistence/rollback test.
